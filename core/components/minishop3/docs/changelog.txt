## [1.12.0-beta1]

### Added
- New extra field type `ms3-repeater` (#299, #301). MIGX-style JSON array of rows with column schema, drag-and-drop sort and auto-assigned `rank`. Backend: `repeater_config` column in `ms3_extra_fields`, `RepeaterFieldService` (decode → normalize → validate pipeline, min/max rows, required/numeric cells). Frontend: `RepeaterField` + `RepeaterSchemaEditor` Vue components, `OrderExtraFieldsSection` for msOrder/msOrderAddress. On the public site, `{$_modx->resource.repeater}` returns an array natively (xPDO `phptype=json`); in `msProducts` listings the value is raw JSON — decode in template (MIGX pattern).
- Option columns for category-products grid (#140, #154). New column type `option`: read-only display of `msProductOption` values via `LEFT JOIN` + `GROUP_CONCAT(DISTINCT ...)`. Sort and `LIKE` filter by option value supported. Configuration in the new "Option column" field type — pick option key from `ms3_product_options`. Backend extracted from `CategoryProductsController` into `CategoryProductsListService`; SQL-injection protection through whitelist on `option.key` (`[a-z0-9_]+`) and field name (denylist of builtin product columns to prevent FETCH_ASSOC overwrite). Inline editing is intentionally disabled for option columns — edit through the product card.
- Inline-edit Select / Combo editors in category-products grid (#155, #157). Two new `editor_type` options for editable columns: `select` (static list from JSON `editor_options`) and `combo` (loaded from API via `editor_reference`). `GridEditorReferenceRegistry` allowlist (currently `vendors`); override URL via `editor_combo_endpoint` only accepted if path starts with `/api/mgr/references/`. `GET /api/mgr/grid-config/category-products` exposes available `editor_references` for the column-config UI. `GET /api/mgr/references/vendors` now also returns a unified `options: [{value, label}]` array; legacy `vendors` key preserved for compatibility.

### Changed
- Manager API contract — per-field `null` payload semantics (#289, #310). Previously every controller path used `isset($data[$field])`, which silently skipped `null` values. Replaced with per-field rules: numeric / required fields (`count`, `price`, `weight`, `label`, `xtype`, `active`) skip `null` to avoid silent zeroing from partial payloads; nullable text / JSON fields (`options`, `select_options`, `description`, address fields) treat `null` as "clear". Affects `OrdersController` (`create`, `updateProduct`, `updateOrder`), `ExtraFieldsService::updateField`, `CustomerAddressManager::update`. Advisory for third-party API clients: if you relied on `null` being a silent no-op for text/JSON fields, that field will now be cleared. Frontend (PrimeVue `InputNumber` clearing to `null`) now works as expected for legitimate "clear" intent.
- Grid filter contract — `direct_filter_keys` now defined on the backend and returned with the grid config (#314, #317). `GET /api/mgr/grid-config/{key}` includes `direct_filter_keys` — list of filter keys sent as direct query parameters (without `filter_` prefix). All other filter keys get `filter_*` prefix. Vue composable `useGridFilterParams` reads the list from the backend, ensures `OrdersGrid` and `CustomersGrid` use the same serialization logic. Removes the duplicated `DIRECT_FILTER_KEYS` constants previously hardcoded in Vue.
- Customer notifications resolve email/phone from the order's `msOrderAddress` first, then `msCustomer`, then `modUserProfile` (#218, #320). Previously the customer record could override the per-order contact when several orders were placed in the same session with different addresses. `recipient['address']` (full order address) and `recipient['customer']` are now both available to plugins/templates; resolved `email`/`phone` are mirrored back into `recipient['customer']` for backward compatibility. `EmailChannel::getRecipientEmail()` aligned with `SmsChannel::getRecipientPhone()` (falls back to `recipient['address']['email']`).

### Fixed
- Product processors lost `Data` and extra-field values on save through `runProcessor` / `Resource\Create::getInstance()` (#297, #298). `Resource\Create|Update` calls `$object->fromArray($properties)` without `ignoreInvalid` — `msProductData` columns simply did not land on the object. Added `ProductDataPayloadTrait` shared by `Product\Create` and `Product\Update`: captures `Data` and flat product-data keys in `beforeSet()`, validates against `loadMap()`-enriched whitelist (`getDataFieldsNames()`), applies in `beforeSave()` for Update or `afterSave()` for Create (where the composite needs the resource id). Alias classes `msProductCreateProcessor` / `msProductUpdateProcessor` for the MODX resolver path used by CSV import.
- Install: orders, statuses, grid_fields and other tables sometimes missing or partially populated (#270, #294). `initial_schema` migration now fails fast with a `RuntimeException` listing problematic tables when `createObjectContainer()` reports failure or post-create `hasTable()` check fails. Self-healing `repair_grid_fields_if_missing` migration restores broken grid configs (handles both missing table and individual empty `grid_key` rows, including the no-op fallout from the #276 double-prefix bug). ALTER migration on `ms3_grid_fields` converts existing `created_at` / `updated_at` from TIMESTAMP to DATETIME (matches the model; fresh installs already get DATETIME).
- Install: garbled Russian seed strings on databases where MODX `charset` system setting is set to `UTF-8` (#307, #308). `phinx.php` now normalises the charset (`UTF-8` → `utf8mb4`, `utf8mb3` → `utf8mb4` for new installs); explicit `database_dsn` or `database_charset` take precedence. Collation resolved with sensible defaults per charset.
- Install: Phinx metadata table created without `table_prefix` on installs with a non-empty prefix (#313, #318). `default_migration_table` now includes the prefix; on upgrade, if a legacy unprefixed `ms3_migrations` table is detected, it is safely renamed to `{prefix}ms3_migrations` before Phinx starts — otherwise Phinx would treat the install as fresh and try to re-run every migration.
- Product save through PUT `/api/mgr/product-data/{id}` (Vue ProductData tab) silently dropped repeater extra-field values (#301 follow-up). The static whitelist in `ProductDataService::updateProductData()` is now extended at runtime with active repeater extra-field keys for `msProductData`. The legacy MODX Save flow already worked via the ProductDataPayloadTrait (#298) once the Vue side serialized the value into a hidden form input.
- Category and Product `class_key` is now auto-injected by the processors when missing or set to `modDocument` (#305, #306, #315). The MODX `Resource\Create` processor reads `class_key` from request properties with `modDocument` as default and ignores the processor's `$classKey` property. Custom `initialize()` in `Product\Create` and `Category\Create` now restores the intended `msProduct` / `msCategory` class_key. Explicit non-default class_key in payload is preserved.
- CSV import for multi-value options (#309, #312). Cells like `"flour, water, salt"` for `comboMultiple` / `comboColors` / `comboOptions` types now produce separate `msProductOption` rows instead of a single string. For single-value or unknown types the comma-separated value is preserved literally — text options are not split. `OptionService::saveProductOptions(..., removeOther: false)` keeps partial-update semantics — options absent from the CSV row are not erased.
- Customer search in the admin grid no longer hijacks browser autofill after a customer save (#286, #319). The customer edit form is now wrapped in `<form autocomplete="off">`, fields have prefixed IDs and explicit autocomplete attributes, password field uses `autocomplete="new-password"`. As a defensive fallback, `searchQuery` is captured before save and restored after the modal closes.
- Orders grid: draft visibility toggle (#302, #303). New "Show drafts" checkbox in the grid header (between Create button and stats) with persistence in `localStorage`; initial value falls back to the `ms3_order_show_drafts` system setting. Backend `applyDraftVisibilityFilter()` consumes the `show_drafts` request parameter (overrides system setting). Tooltip on the stats block clarifies that the totals count only "placed" orders and ignore drafts.
- Stats query in `OrdersController::getOrdersStats()` previously broke when address-related filters (`filter_customer`, `filter_email`, `filter_phone`) were active — the address JOIN was missing in stats. Now added conditionally when an address filter is present.
- Schema XML synced with the actual model classes after the 1.11.0 `msOptionGroup` change (#322). `core/components/minishop3/schema/minishop3.mysql.schema.xml` had `msOption.modcategory_id` (renamed to `option_group_id` in 1.11.0) and was missing the `msOptionGroup` object entirely. Runtime source of truth remains `src/Model/mysql/*`; the XML is kept as a reference document and now matches it.

## [1.11.1-beta1]

### Fixed
- `msProducts` / `msCart` / `msGetOrder` with `includeThumbs` returned an SQL syntax error in 1.11.0-beta1 (#293). The new `ProductThumbnailJoin` helper wrapped `$modx->getTableName()` result in extra backticks; xPDO already escapes the name itself, so runtime SQL had triple backticks around the table and MySQL rejected the statement. Storefront catalog listings with thumbnails were empty until reload. Fixed by stripping the outer backticks in the sprintf template.
- Package upgrade to 1.11.0-beta1 failed on MODX installs where `modx_transport_packages.metadata` is `TEXT` (#296). The full project changelog (~33 KB of history since 1.0.0-alpha) plus license + readme + requires, serialized into package attributes, overflowed the 65 535-byte limit. Transport-package metadata now contains only the current release block from the changelog (~7 KB); the full file remains in `core/components/minishop3/docs/changelog.txt` inside the installed package.

## [1.11.0-beta1]

### Added
- New `msOptionGroup` model replaces `modCategory` for grouping product options (#10). Migration converts existing `msOption.modcategory_id` → `option_group_id` automatically (each distinct `modcategory_id` becomes a row in `ms3_option_groups` using `modCategory.category` as name). Admin: separate "Option Groups" tab next to "Options" with CRUD, drag-and-drop ordering, options-per-group counter.
- Public `window.ms3.refresh()` storefront JS API and `ms3:refresh` DOM event (#274) for integration with third-party AJAX components that replace catalog DOM (mFilter / mSearch2 / custom AJAX / infinite scroll). The component dispatches `ms3:refresh` after its DOM swap — MS3 re-binds `ProductCardUI` / `QuantityUI` state. MS3 does NOT listen for vendor-specific events; dependency direction is component-→-MS3.
- Manager API endpoint `POST /api/mgr/orders/{id}/recalculate-cost` and "Recalculate cost" button in the order admin (#212). Three modes: `auto` (DefaultDelivery/DefaultPayment by fields, no external provider calls), `manual` (operator-provided `manual_delivery_cost`), `force_provider` (explicit provider call in try/catch). Honours discounts via `PriceAdjustment` and total clamp via `OrderService::clampComputedTotal()`.
- Negative additional cost for delivery and payment methods (#211): the `price` field now accepts fixed discounts (`-10`) and percent discounts (`-10%`). Common normalizer `MiniShop3\Utils\PriceAdjustment` shared between manager API and legacy processors.
- Negative total guard `OrderService::clampComputedTotal(?msOrder, float, float, float = 0.0)` (#265): when sum of cart + delivery + payment costs goes below zero (e.g. misconfigured discounts), total is clamped to 0 and a `LOG_LEVEL_WARN` line with the breakdown is written. Wired into all calculation paths.
- Vue admin: live "Discount" / "Markup" badges on the `price` field of delivery/payment edit forms (#265).
- Validation rules editor for deliveries now lists model fields and Object Extension fields for `msOrder` / `msOrderAddress` (#215) in addition to the static set.
- Order fields tabs: "Configure fields" empty-state hint and conditional action bar visibility on Info / Address tabs (#182).
- Import: product `stock` field is now available in the field mapping (#283), with auto-mapping of typical CSV headers (`stock`, `remains`, `quantity`, `qty`).
- Web API for customer profile: `POST /api/v1/customer/add` (quick profile field update incl. extra fields, #241/#261), `POST /api/v1/customer/changeAddress`, `GET /api/v1/customer/email/verify` (with HTML redirect support), `POST /api/v1/customer/email/resend-verification` (#226).
- System settings: `ms3_email_verification_url`, `ms3_email_verification_success_url` for customizing the email-verification flow.

### Changed (breaking)
- **Storefront snippets — numeric placeholders contract** (#242, breaking). Plain placeholders (`cost`, `cart_cost`, `delivery_cost`, `price`, `weight`, …) are now plain `float` for arithmetic and Fenom `|number`. Display strings with locale / currency / unit live in `*_formatted`. Removed `formatPrices` no-op in `msProducts` and `msOrderTotal`. Migration: change `{$order.cost}` (which used to render `5 300 ₽`) to `{$order.cost_formatted}`, or keep `{$order.cost}` only for arithmetic / `|number`. Affects `msOrder`, `msGetOrder`, `msCart`, `msProducts`, `msOrderTotal`, default `ms3_order.tpl`.
- **Schema — `msOption.modcategory_id` → `msOption.option_group_id`** (#10, breaking for direct DB readers). Data migration is automatic. Custom code reading `modcategory_id` directly must switch to `option_group_id`; the join alias `category_name` in `OptionLoaderService` / `CategoryOptionService` is renamed to `group_name`. Snippet `msProductOptions` filters/sorts by `group_name`.
- **Manager API — `GET /api/mgr/options/modcategories` removed**, replaced by `/api/mgr/option-groups` (CRUD + reorder + bulk delete + per-group options count).
- `msCart` snippet no longer suppresses output on `?msorder=...` by default (#249) — the cart loads and renders the chunk as usual, so mini-cart blocks in the global layout keep working on the "thank you" page. New `hideOnThanks=1` parameter brings back the previous "blank on thanks page" behavior for a specific call.
- `Processors\Product\Update`: option deletion now applies on save (#199 follow-up). Form options are captured in `beforeSet` into `$ms3ProductFormOptions` and passed to `ProductDataService::saveOptions(..., removeOther: true)` after the parent `afterSave` — avoids MODX 3 quirk where the processor's `options` property is often empty post-save.
- `ProductDataService::saveCategories()`: missing `categories` key in the form payload no longer wipes extra category links (#238). Behavior is now symmetric with `saveLinks()` — explicit empty array still clears, but absence of the key (tab not rendered yet) is a no-op. Integrations relying on "no `categories` in POST → clear all" must pass `categories: []` explicitly.
- Web API `POST /api/v1/customer/add` allows all columns present in the `msCustomer` xPDO map (including Object Extension after `loadMap()`), with an explicit denylist of sensitive/system fields (#261). Rakit-validation preserved for `first_name` / `last_name` / `email` / `phone`; other allowed columns are normalized by `phptype`.

### Fixed
- Product duplicate via MODX context menu: option values now copy over to the new product (#257). After `modResource::duplicate()`, `OptionService` re-syncs `ms3_product_options` rows from the source.
- `Processors\Product\Create`: empty option fields no longer wipe options on save. Aligned with `Update` — sync only when the request contained `options-*` keys.
- Plugin events that mutate data via `returnedValues` (#219, #221): `msOnBeforeSendNotification`, `msOnBeforeImport`, `msOnImportRow`, `msOnProductsLoad`, `msOnProductPrepare` apply mutations from the MODX `returnedValues` channel; `Cart::changeOption`, `Customer::validate`, `Customer::getOrCreate`, `OrderStatusService::change`, `OrderUserResolver::getUserId` consume merged `$response['data']` after `invokeEvent`.
- Option category tree for nested catalogs and multi-store setups (#237): tree returns `msCategory` (selectable) plus `modResource`/`modDocument`/`modWebLink` with `isfolder=1` (navigation-only) — no system setting required.
- Product list duplicates on `includeThumbs` (#281): one thumbnail per product via shared `ProductThumbnailJoin` helper in `msProducts`, `msCart`, `msGetOrder`. Fixed `parent` → `parent_id` typo in `msGetOrder`.
- Delivery / payment numeric fields can finally be cleared from the admin form — the controller no longer silently drops `null` values (`isset` → `array_key_exists`).
- Email verification flow: link in the email points to Web API by default (`api.php?route=…/email/verify&token=…&html=1`), with optional custom URL via `ms3_email_verification_url` (#226).
- Phinx defensive checks added in 1.10.x-era seed migrations no longer skip every install due to double `table_prefix` (#276): API methods (`hasTable`, `$this->table()`, `hasColumn`) now receive unprefixed names; raw SQL keeps `{$prefix}name`. Initial schema's foreign-key step also fixed (FK constraints were never being created on fresh installs).
- Many smaller fixes — see project CHANGELOG.md for details.

## [1.10.1-beta1]

### Fixed
- Manager API now invokes `msOnBefore/Create/Update/Remove OrderProduct` events when adding, updating, or removing order line items via the Vue admin (#208, closes #207). Before-hooks may abort with HTTP 400; after-hooks are observe-only and their failures are logged at WARN level (`persistence already done`) without returning a 4xx — the row is already in DB. Previously third-party plugins (ms3PromoCode etc.) silently missed these events.
- Product Options tab: switching between option groups no longer wipes user-entered values (#230). All groups are kept mounted via `v-show` instead of `v-if`-style remount, so per-field local state and hidden inputs survive tab switches and reach the form on submit.
- Cleared dangling `msOption.modcategory_id` references when a `modCategory` is removed (#228). Plugin subscribes to `OnCategoryRemove` and resets the link to 0, mirroring how MODX core handles `modChunk` / `modPlugin` / `modSnippet` / `modTemplate` / `modTemplateVar` on category removal. Prevents the duplicate "no group" tab in the product options UI when a third-party component is uninstalled.
- `OrderFinalizeService` now invokes registered `msOnBeforeMgrCreateOrder` / `msOnMgrCreateOrder` instead of non-existent `msOnBeforeFinalizeOrder` / `msOnFinalizeOrder` (#217). The old names were never registered as `modEvent`, so plugins could not subscribe via the UI.
- Import → TV fields panel uses the correct setting key `ms3_template_product_default` (was: non-existent `ms3_product_default_template`), so the panel lists only TVs bound to the configured default product template instead of every TV in the system (#210).
- Added missing lexicon `ms3_cart_get_success` in `lexicon/{ru,en}/cart.inc.php` — the key was used by `Cart::get()` but missing from translations, producing `Language string not found` warnings in MODX logs (#223, closes #222).
- `ServiceRegistry` no longer logs DEBUG noise for missing default optional override paths (`core/config/ms3.services.php`, `core/config/ms3.services.d/`) on stock installations (#225, closes #224). The DEBUG log is preserved when the operator explicitly sets `ms3_services_config` / `ms3_services_addons_dir` system settings to a missing path.

### Refactored
- Deleted 7 ExtJS UI files (settings/option/* + category/option.*) and 22 PHP processors (Settings/Option, Category/Option), ~2600 lines of legacy code.
- Order edit screen: provide/inject instead of props chain (#196, #204). `ORDER_CONTEXT_KEY` symbol provides the shared ref/action/helpers set to all tabs; composables `useOrderFormatters`, `useOrderFieldHelpers`, `useOrderLogFormatters` extract what used to be inline helpers. ### Fixed

JSON-only auto-sync still forces `removeOther=false` to preserve category-only options (regression guard for #153/#158).
- Checkbox-type options on the product form no longer render as a 25%-wide sliver on top-aligned labels (root cause `anchor: '25%'` in legacy ms3.utils.js is gone along with the ExtJS UI).
- Category tree in the options dialog no longer lists non-category resources; filters by `class_key = MiniShop3\\Model\\msCategory` (exact) and uses an accurate COUNT-based leaf flag instead of `isfolder`.
- Independent checkboxes in category tree: selecting/deselecting a parent no longer cascades to children (PrimeVue Tree's default propagation replaced by a custom checkbox render).
- Optional `modcategory_id` on option create/update (null/empty payload is coerced to 0 for the NOT NULL column).
- Dialog styles now apply in teleported PrimeVue Dialog markup (class='ms3-option-dialog vueApp' on the dialog root + .ms3-option-dialog scoped selectors).
- DatePicker for `datefield` no longer sends a day-early value — `toISOString()` (UTC) replaced by local `getFullYear/getMonth/getDate` when serializing into the hidden POST field.
